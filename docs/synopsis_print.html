1. Project Title

Library Management System

2. Introduction

A Library Management System is a web-based application that helps manage the daily activities of a library. It stores information about books, authors, categories, and members in a database. It also helps keep track of issued books, returned books, overdue books, and fines. The main purpose of this project is to make library management easier, faster, and more organized. Using HTML, CSS, JavaScript, Python Flask, and PostgreSQL, the system reduces manual work and makes it easier to access and update library records.

3. Problem Statement

Managing a library involves maintaining records of books, authors, categories, members, and book borrowing activities. When these records are handled manually, it can become difficult to find books, check their availability, update member details, and keep track of issued and returned books. Manual record-keeping may also lead to duplicate entries, missing information, and errors. Another challenge is tracking book issue dates, due dates, overdue books, and fines. Without a proper system, librarians may find it difficult to identify overdue books and maintain accurate records of library transactions. Managing relationships between books, authors, members, and loan records can also become complicated when the information is not properly organized.

To solve these problems, a Library Management System is proposed using HTML, CSS, JavaScript, Python Flask, and PostgreSQL. The system will provide a centralized database to store, retrieve, and update library information efficiently. It will also use important DBMS

4. Objectives

  • To maintain book, author, category, and member records accurately.
  • To manage book issuing and returning smoothly with real-time inventory updates.
  • To track overdue books and calculate fines automatically without manual intervention.
  • To reduce manual work and eliminate duplicate records using relational normalization.
  • To apply core DBMS concepts such as joins, subqueries, aggregate functions, triggers, views, indexes, and transactions.
  • To provide a simple, responsive, and user-friendly web interface for seamless library administration.

5. Scope of the Project

  • Book Management: Add, view, update, and delete book records along with ISBN, category, publisher, and edition year.
  • Member Management: Store and manage library member profiles, membership types (Student/Faculty), status, and contact details.
  • Issue and Return: Record book lending and return activities with automated timestamp tracking.
  • Overdue Tracking: Automatically identify overdue loans and compute applicable daily late fees.
  • Database Operations: Perform multi-parameter searching, filtering, sorting, and analytical reporting across all tables.
  • Data Integrity: Enforce primary keys, foreign keys, unique constraints, and check constraints to prevent invalid data entries.
  • Database Analysis: Generate actionable operational insights using SQL queries, views, and aggregate functions.

6. Proposed System

The proposed system is a web-based application with a frontend developed using HTML, CSS, and JavaScript, a backend developed using Python Flask, and PostgreSQL as the database. Users can manage books and members, issue and return books, and check overdue records through the application. The backend processes user requests and communicates with the PostgreSQL database to store and retrieve information. The system also uses advanced SQL concepts, including joins, subqueries, aggregate functions, PL/pgSQL functions, triggers, views, indexes, and transactions. These features help maintain data accuracy and make library operations more efficient.

7. Database Design

7.1 Entities and Attributes

1. Authors

  • author_id (Integer, Primary Key, Auto-increment)
  • first_name (Varchar, Author's first name, Not Null)
  • last_name (Varchar, Author's last name, Not Null)
  • email (Varchar, Contact email address, Unique)

2. Categories

  • category_id (Integer, Primary Key, Auto-increment)
  • category_name (Varchar, Category title, Unique, Not Null)
  • description (Text, Brief summary of category topics)

3. Books

  • book_id (Integer, Primary Key, Auto-increment)

  • isbn (Varchar, 13-digit International Standard Book Number, Unique, Not Null)
  • title (Varchar, Full title of the book, Not Null)
  • category_id (Integer, Foreign Key referencing Categories)
  • publisher (Varchar, Publishing company)
  • publication_year (Integer, Year of publication)
  • total_copies (Integer, Total physical stock count, Check >= 0)

  • book_id (Integer, Primary Key, Foreign Key referencing Books)
  • author_id (Integer, Primary Key, Foreign Key referencing Authors)

5. Members

  • member_id (Integer, Primary Key, Auto-increment)
  • member_code (Varchar, Unique college card identification, Unique, Not Null)

  • last_name (Varchar, Member's last name, Not Null)

  • phone (Varchar, Contact telephone number)
  • address (Text, Residential postal address)
  • membership_type (Varchar, Category: Student, Faculty, Staff)
  • status (Varchar, Status: Active, Suspended, Expired)
  • joined_date (Date, Date of registration)

6. Loans

  • loan_id (Integer, Primary Key, Auto-increment)
  • book_id (Integer, Foreign Key referencing Books)
  • member_id (Integer, Foreign Key referencing Members)

7.3 Relational Schema

• Authors: Authors(author_id, first_name, last_name, email)
• Categories: Categories(category_id, category_name, description)
• Books: Books(book_id, isbn, title, category_id, publisher, publication_year, total_copies, available_copies)
• Book_Authors: Book_Authors(book_id, author_id)

7.4 Primary Keys and Foreign Keys

Primary Keys (PK): Authors (author_id), Categories (category_id), Books (book_id), Book_Authors (book_id, author_id), Members (member_id), Loans (loan_id).
Foreign Keys (FK): Books.category_id → Categories, Book_Authors.book_id → Books, Book_Authors.author_id → Authors, Loans.book_id → Books, Loans.member_id → Members.

8. SQL Implementation

  • DDL (Data Definition Language): CREATE TABLE and ALTER TABLE to define relational structures, data types, and primary/foreign keys.
  • DML (Data Manipulation Language): INSERT, UPDATE, and DELETE to perform record transactions safely.
  • Basic SQL Queries: SELECT, WHERE, ORDER BY, and DISTINCT to query, filter, and sort library inventory.
  • Integrity Constraints: PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, and CHECK to ensure domain integrity.
  • Joins: INNER JOIN and LEFT JOIN to retrieve composite book-author and loan-member data across relations.
  • Nested Subqueries: Correlated and non-correlated nested subqueries to evaluate multi-condition lookups.
  • Aggregate Functions: COUNT(), SUM(), AVG(), MIN(), and MAX() for library stock summaries.
  • GROUP BY and HAVING: To aggregate borrowing volumes by genre and filter high-circulation categories.
  • Functions and Triggers: PL/pgSQL stored procedures and triggers to automate available copy decrement on issue and increment on return.
  • Views and Indexes: vw_active_loans view and B-tree indexes on ISBN and Member Code for sub-millisecond retrieval.
  • Transactions: BEGIN, COMMIT, and ROLLBACK blocks ensuring strict ACID guarantees during multi-table loan workflows.

11. Conclusion

The Library Management System helps make library work easier and more organized by managing book details, member information, and book issue and return records in one place. It reduces the need for manual record-keeping and helps avoid common mistakes such as duplicate entries and incorrect information. By using HTML, CSS, JavaScript, Python Flask, and PostgreSQL, we have developed a system that makes storing, updating, and finding information more convenient.

Through this project, we also gained practical knowledge of important DBMS concepts such as keys, constraints, joins, subqueries, aggregate functions, views, indexes, transactions, functions, and triggers. It helped us understand how a database works in a real-world application and how different technologies can be connected to build a useful system. In the future, more features like barcode scanning, due-date reminders, and online book reservations can be added to make the system even more useful.
